## 5. Decision points

Judgment-bucket calls. Surfaced, not self-decided (`product-completion-first.md` MUST-4).

### D1 — #86 vs #87: which reachability reading ships?

Two independent Step-7c drafts of one net-new rule, same inbox path. Both cut the same unsound
commit-ratio heuristic independently — the strongest signal in the pair. They disagree on
exactly the point #86 flagged for template judgement:

- **#86** added a reachability floor (`workspaces/**`, `.session-notes.d/**`,
  `.wave-tracker.d/**`) because the original globs never fire — the destructive act is a Bash
  build invocation touching neither build-script nor artifact globs. Pro: the rule can
  actually fire. Con: broad globs on a rule that cascades to every consumer.
- **#87** declined to widen, recording the unreachability as a known limitation with the
  reviewer gate as enforcement surface. Pro: no glob inflation; honest about the limit. Con:
  ships a rule whose clause 3 cannot fire from rule-load.

**Recommendation: take #86 as the base** (authored against current 2.24.0; #87 is against
2.23.22 despite landing later) **and graft #87's two contributions** — the carve-out that a
human's markup of the readable copy is an expected INPUT requiring backport (not a prohibited
act), and its explicit statement of the enforcement-surface limit. Then **narrow #86's globs**
before relay, since #86 itself asks the template to judge that.
Con, stated: this is a merge of two drafts, so neither's redteam applies wholly to the result;
the grafted rule needs its own round before relay.

### D2 — Do #78 and #79 get fixed locally, or only as proposals?

Both are defects in SYNCED artifacts (`.coc-obsoleted`, `rules/`), so a local fix is Class-A
non-durable — rebuilt away by the next `/sync-to-use`.

- **Proposal only** — Pro: the durable surface; matches `artifact-flow.md`. Con: every consumer
  pulling before loom ingests still gets the self-deleting manifest and the absent rule.
- **Local fix + proposal** — Pro: consumers pulling from this template stop being harmed now.
  Con: the local edit is reverted at the next sync, so it must not be mistaken for the fix.

**Recommendation: both, explicitly labelled.** #78 in particular is actively destructive —
consumers delete shipped files by following the documented contract — and the local repair
costs one line per entry. The proposal remains the durable fix; the local edit is a stopgap
whose non-durability is stated in its own commit body.
