## 5. Decision points

Two judgment-bucket items. Neither is self-decided.

### D1 — Register Gate C as a required status check?

**Live state, verified not assumed:** `required_status_checks.contexts` currently holds exactly
one entry — `Sync invariants (local-fix discard + obsoleted disjointness)` — matching that job's
`name:` byte-for-byte. `enforce_admins: false`. Gate C is NOT registered; it reports only.

**Recommendation: NOT YET — revisit after it has run on ~5 more PRs.**

_Pros of registering now:_ the ratchet becomes binding rather than advisory; the manifest cannot
silently rot again; it matches how Gate A/B is already treated.

_Cons, stated honestly:_ Gate C is one day old and has already had one real bug (the PyYAML
date-type defect that misclassified all 70 reconciled entries). Registering a young gate whose
failure mode was recently "confidently wrong in the worst direction" risks blocking legitimate
PRs on a gate nobody yet trusts — which is how a required check gets routinely `--admin`-bypassed,
and a bypassed required check is worse than an advisory one because it teaches the bypass.
`enforce_admins: false` means registration would not actually compel anyone today either.

_What would change the recommendation:_ ~5 PRs of clean operation with at least one genuine
catch. That is the evidence I do not have.

### D2 — Do the 17 duplicate groups need per-entry `ingest_note` pairing?

**Recommendation: NO — leave as-is.**

_Pros of pairing:_ Gate-1 reading entry N sees its sibling named inline, with no need to consult
the triage block.

_Cons:_ it duplicates information that already exists in one place, and duplicated information
is what this entire cycle was spent un-drifting. 17 groups × per-entry notes is 41 edits to
restate a table that is already correct and machine-checked (the group count is asserted equal
to reality). The failure mode being avoided — Gate-1 processes a file N times independently — is
addressed by the centralised list.

_What would change it:_ evidence that a Gate-1 reviewer works entry-by-entry without reading the
triage block. That is loom's workflow, not observable from here.
