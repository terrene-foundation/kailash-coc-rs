## Non-Functional Requirements

| ID     | Category                   | Target                                                                                                | Spec                          |
| ------ | -------------------------- | ----------------------------------------------------------------------------------------------------- | ----------------------------- |
| NFR-01 | First-build latency        | Cold build of slim base (no heavy ML) documented; target ≤ ~10 min on arm64 laptop                    | base-image, cli-toolchain     |
| NFR-02 | Warm-start latency         | `docker compose up` on built image ≤ ~30 s to shell + Postgres healthy                                | container-topology            |
| NFR-03 | Image size                 | Slim base documented, target ≤ ~2.5 GB; heavy ML layer separate                                       | base-image                    |
| NFR-04 | Multi-arch                 | Builds on linux/arm64 AND linux/amd64 from one Dockerfile                                             | ci-multiarch, base-image      |
| NFR-05 | Secret isolation           | Zero secrets in any image layer (`docker history`) AND zero in any committed file                     | credentials-secrets           |
| NFR-06 | Node runtime floor         | Node 20 LTS (Gemini runtime ≥20; guard ≥18) pinned explicitly                                         | cli-toolchain                 |
| NFR-07 | Reproducibility            | Base pinned by digest; CLIs pinned to major line; lockfiles hash-locked                               | base-image                    |
| NFR-08 | Fail-visible auth          | Missing API key fails at CLI-use with a clear message; no silent fallback, no baked default key       | credentials-secrets           |
| NFR-09 | Throwaway Postgres creds   | `postgres`/`postgres`, Postgres NOT host-published (internal net only), documented dev-only           | services, credentials-secrets |
| NFR-10 | Cross-template consistency | 80% agnostic base identical-by-construction with `kailash-coc-py`, rs delta (Ruby + Rust) isolated    | provenance-sync               |
| NFR-11 | Public-surface portability | No operator/host identifiers; bind-mounts via `${HOME}`; org slugs limited to public terrene/esperie  | credentials-secrets           |
| NFR-12 | Shared-env integrity       | Base + overlay install to the SAME Python env AND the SAME Ruby `GEM_HOME` (no-rebuild feature works) | extensibility                 |
