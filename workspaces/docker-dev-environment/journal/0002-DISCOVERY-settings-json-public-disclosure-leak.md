# 0002 — DISCOVERY — Pre-existing public-disclosure leak in `.claude/settings.json`

**Date:** 2026-05-27 · **Phase:** /analyze · **Class:** disclosure (same as #260/#252)

## Finding (verified against the live file)

`.claude/settings.json` ships, in a template destined for a PUBLIC repo:

- Lines 36–43: hardcoded operator-absolute paths in `permissions.allow` —
  `Edit/Write/Read(/Users/<operator>/repos/loom/kailash-*/**)`,
  `Edit/Write(/Users/<operator>/repos/loom/.claude/**)`,
  `Edit/Write/Read(/Users/<operator>/repos/kailash-*/**)`.
- Line 3: `"description": "Kailash COC Claude (Python) ..."` — mislabels the **rs**
  template as "(Python)" (copy-paste from the py emission).

## Why it matters

This is exactly the public-surface disclosure class the operator flagged for the Docker
work — operator home-dir layout + machine-specific paths committed to a public repo,
permanently extractable from git history. The Docker artifacts MUST NOT replicate this
pattern (bind-mounts via `${HOME}`, never literal `/Users/...`).

## Disposition (recommended)

- This is a PRE-EXISTING leak in an **emitted/synced** artifact (`settings.json` is
  regenerated by loom `/sync`). A local hand-edit here would be clobbered on the next
  sync AND would not fix the sibling templates (py etc.) carrying the same leak.
- Correct fix: at the **loom emitter** — so every `kailash-coc-*` template is corrected
  together. The legitimate channel from this USE-template is a `/codify` proposal
  (artifact-flow). Surfaced to the user for disposition; NOT silently patched.
- Out of the Docker work's direct scope, but same disclosure class → flagged loudly.
